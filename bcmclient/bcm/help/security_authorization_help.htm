Security Authorization

For entities created in MDM, data has to be authorized for future access to these entities. A user can be assigned multiple leaf nodes in each authorizing hierarchy. The user can then create entities authorized for only one of the leaf nodes in these hierarchies. For example, a user who is authorized for access to items can access data that is authorized (eg., BOM Components) for either of these nodes. However, the user can create an entity authorized for only one of the two nodes. This constitutes the Security Context, that is set prior to creating a new entity. You have to specify a leaf node in each hierarchy for which a new entity has to be authorized. 

The Security Authorization page is displayed when you log into MDM. After logging in, you can change the default security context. You can also access the Security Authorization page after logging into MDM. Click the Tasks > Manage Security link to view the Security Authorization page. 

Security authorization can be done at multiple levels.

 What you can do

Setting the Security Context

  1. Select the Authorizing entity.
  2. Select the option corresponding to the required authorizing entity.

    Note: By default, the first record is selected in all the tabs. You can select a different record for the required authorizing entities in the corresponding tabs. 
  3. Click the Save button.
  4. Click the Cancel button to cancel the security authorization process.
    The Cancel button is not displayed only when you are logging into MDM for the first time. However, it is displayed when you have saved the changes and revisit the page by selecting Tasks > Manage Security for the login session.

    The context is now set to the selected authorizing entity. The context is applied when you are creating new entities in MDM. For example, when creating an BOM Components, you need to search for a list of items to be added to the BOM Components. You may be authorized for multiple leaf nodes of items in the hierarchy. However, the items listed will be authorized against the security context that was set by the user.
