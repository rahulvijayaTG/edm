Measure Dimensionality

When defining the dimensionality of a measure, remember the following rules (as they are in Demand Manager 6.1.5).

 

 What you can do

Dimensionality Rules

Bi-Direction Measure rules

  • A Bi-directional measure should have atleast one KEY & BLOCK (time) dimension 
  • The aggregation type has to be SUM in all dimensions. It cannot vary for time. 
  • It can have exactly one lower bound and multiple upper bounds 
  • It can have exactly one IOLEVELs combination. It should have one IOLEVEL in a dimension for each IOLEVEL combination. IOLEVEL should be enveloped between upper and lower bounds.
  • Lookup levels cannot be defined.
  • It does not support string datatype.
  • A unique path must exist between a upper and lower bound (aggregation & disaggregation).

SinglePoint Measure Rules

  • A SinglePoint measure should have atleast one KEY & BLOCK (time) dimension.
  • The aggregation type in non-key dimension is not allowed. It can be either SUM or AVERAGE in block (time usually) dimension, if specified explicitly (else no aggregation will be supported).
  • It can have exactly one lower bound and multiple upper bounds. 
  • It can have multiple Iolevels combinations. 
  • It must have one IOLEVEL in a dimension for each IOLEVEL combination. IOLEVEL should be enveloped between upper and lower bounds.
  • Multiple lookup levels can be defined. Each Lookup-level should be enveloped between upper and lower bounds. 
  • It does not support string datatype.

COMMENT measure rules

  • It requires one dimension. No constraint such as KEY & BLOCK dimension.
  • Aggregation is not supported in any dimension.
  • It can have exactly one lower bound and multiple upper bounds.
  • It supports only string type data. 
  • It can have multiple IOLEVELs combinations. It should have one IOLEVEL in a dimension for each IOLEVEL combination. IOLEVEL should be enveloped between upper and lower bounds. 
  • Multiple lookup levels can be defined. Each Lookup-level should be enveloped between upper and lower bounds.

Adding a new dimension

  1. You can only add a new dimension for a new/duplicate measure. 
  2. Select the dimension from the Dimension drop down box and define the type, aggregation (if allowed), Upper bound, lower bound and the lookup levels (if applicable). 
  3. Click on Apply button.

Modifying properties in a dimension

  1. Select the dimension from the Dimensionality table and click on Modify button.
  2. Enter the specifications in the bottom panel and click on Apply button. You can modify the Upper bound, lower bound and the lookup levels (if applicable) for a new/duplicate and an existing measure.

Removing a measure’s dimension

  1. You can only remove a dimension for a new/duplicate measure.
  2. Select the measure from the top table, click on Remove button.
  3. Click on Finish button to save the measure’s definition to the database.

Adding a IO Level combination

  1. To add a new IO Level combination, click on New button.
  2. Set the IO Level for each dimension the measure is valid in.
  3. You can add as many IO Level combinations as the business requires.
  4. To remove a IO Level combination, select the IO Level and click on Remove.
  5. To accept all changes, click on Submit button. The dialog box closes.
  6. Click on Finish button to save the measure’s definition to the database.
